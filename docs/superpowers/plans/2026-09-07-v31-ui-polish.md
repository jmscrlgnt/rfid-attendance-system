# JCG Attendance System v3.1 UI Polish Implementation Plan

**Goal:** Improve responsiveness and visual polish of the Designer-based WinForms UI without changing working attendance, authentication, SQLite, or admin business logic.

**Architecture:** Keep the existing forms/services/repositories split. Changes are limited to Designer layout files, theme helpers, and small presentation-only code where needed.

**Tech Stack:** C# WinForms, .NET Framework 4.8, SQLite.

## Global Constraints
- Preserve the existing SQLite data location and schema.
- Preserve all service/repository behavior and public form workflows.
- Keep every user-facing form Visual Studio Designer-compatible (`.cs`, `.Designer.cs`, `.resx`).
- Do not add external UI packages.

### Task 1: Responsive login
- Replace the directly-centered login panel with a nested center-host layout so the card cannot collapse or clip.
- Keep keyboard/default-button behavior and authentication logic unchanged.

### Task 2: Records filter layout
- Give filter rows explicit usable heights.
- Keep all four action buttons visible at normal DPI/resolutions.
- Improve spacing and grid readability.

### Task 3: Dashboard and attendance polish
- Add subtle metric-card accent strips and consistent grid selection/alternating-row styling.
- Reduce unused attendance search/results whitespace while keeping details prominent.

### Task 4: Students, settings, audit, shell consistency
- Improve grid style, action spacing, sidebar/header/content spacing, and admin-card consistency.
- Keep existing role-based visibility and actions unchanged.

### Task 5: Verification and delivery
- Add regression checks for the responsive login and records action row.
- Run Designer structure, modernization, SQLite/schema, SQL arity, XML/resource, and ZIP integrity checks.
